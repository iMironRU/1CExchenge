# 1CExchenge — реестр обменов и переходов типовых конфигураций 1С

Цель: по полным поставкам типовых конфигураций 1С составить реестр, **из какой типовой
в какую есть обмен (синхронизация) и переход (перенос данных)**, с доказательством
в виде конкретного файла или объекта поставки.

Результат: [`REGISTRY.md`](REGISTRY.md) (матрица «из → в» и список связей),
[`data/registry.json`](data/registry.json) (машиночитаемый), `data/registry.csv` (для Excel).

## Источники

- **Шаблоны поставок** — `C:\.temp\tmplts\<vendor>\<config>\<version>\` (каталог шаблонов 1С,
  куда ставятся полные дистрибутивы; там же лежат новые поставки).
- **Ссылки на дистрибутивы** — API Апдейкона (https://upd.imiron.ru): `/api/versions`, `/api/files`.

## Где в поставке лежат обмены

1. **Файлы поставки** (сканер `tools/scan-templates.js`):
   - `Обмены данными\Обмен с конфигурацией <X>\` — правила КД2: `Правила конвертации.xml|zip`
     (в zip: `ExchangeRules.xml`, `CorrespondentExchangeRules.xml`, `RegistrationRules.xml`),
     `Правила регистрации.xml`, `Совместное использование.htm`, инструкции;
   - `AddFiles\Переходы с других конфигураций\` (УТ 11) — синхронизация с БП 2.0/ДО/Розницей,
     переходы с ТиС 7.7, обработки перехода;
   - `Conv*\` — переходы с конфигураций 7.7 (обработка `.ert` + правила КД2 `.xml`).
   - С УТ 11.6 внешние обработки перехода (УПП/ЗУП/БП → УТ 11) **убраны из поставки** и
     публикуются отдельным файлом на странице версии releases.1c.ru.
3. **Пакеты перехода на releases.1c.ru** — файлы «Для перехода с …» среди файлов последней версии
   (`/api/files` Апдейкона), разметка названий — `releaseFiles` в `data/annotations.json`.
2. **Внутри CF** (сканер `tools/scan-cf.js`, через `ibcmd`, лицензия не нужна):
   - планы обмена с макетами `ПравилаОбмена` / `ПравилаОбменаКорреспондента` / `ПравилаРегистрации`;
   - EnterpriseData: план `СинхронизацияДанныхЧерезУниверсальныйФормат`, варианты настройки
     (корреспонденты) и объявленные версии формата (`ВерсииФормата.Вставить(...)`). Модуль менеджера
     общий для УТ/КА/ERP, поэтому корреспондент засчитывается, только если его вариант реально
     добавляется в `ПриПолученииВариантовНастроекОбмена`;
   - встроенные обработки перехода (`ПомощникПереходаС…`, `ЗагрузкаДанныхИз…`) — по ручной разметке.

## Запуск

```powershell
node tools/scan-templates.js      # файлы поставок      -> data/templates.json
node tools/scan-cf.js             # CF (≈5–7 мин/поставка, кеш в work/) -> data/cf/*.json
node tools/fetch-files.js         # файлы последних версий из API Апдейкона -> data/catalog-files.json
node tools/build-registry.js      # -> data/registry.json, data/registry.csv, REGISTRY.md
node tools/build-page.js          # страница с матрицей -> work/page/registry.html
```

Страница опубликована как артефакт: https://claude.ai/artifact/F7cwxeovhDSFgpzhjsKerp
(шаблон `tools/page/template.html`, каталог типовых — снимок `/api/configs` в `data/catalog-ru.json`).

`scan-cf.js --only trade/11_6` — одна поставка. Повторный запуск пропускает готовые шаги
(база, список объектов, выгрузка) и только переанализирует.

Ручная разметка — `data/annotations.json`: обработки в файлах поставки (`processings`),
встроенные обработки CF (`cfProcessors`), планы обмена вне реестра (`skipPlans`).
Рабочий каталог `work/` (ibcmd-базы ≈1,5 ГБ на поставку, выгрузки) в git не попадает.
